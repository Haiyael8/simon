# תוכנית – Milestone 2: משחק מלא מקצה לקצה

מקורות: PRD §4.2, ARCHITECTURE §2.3–2.4 + ADR-2/3/5, DESIGN §1.1 (טבלת הקצב) ו-MILESTONES (Milestone 2). הקוד הקיים (Milestone 1) הוא נקודת המוצא: `App` עם `useState` לניווט, `Board` סטטי, `HomeScreen` סטטי.

## 1. מה בונים, בפשטות
משחק אמיתי: לוחצים "התחל משחק", המשחק מציג רצף עם אור וצליל, השחקן משחזר, כל שלב מוסיף צבע, טעות = הפסד, שלב 10 = ניצחון. הודעת סיום עם "אישור" שמחזירה לבית. **אין** היסטוריה (Milestone 4), **אין** השהיה/"המשך משחק" (Milestone 3), **אין** PWA.

## 2. תלויות חדשות
- `canvas-confetti` (+ `@types/canvas-confetti` ב-devDependencies). זו התלות היחידה החדשה; האודיו נעשה עם Web Audio API מובנה.

## 4. מצב המשחק (Reducer)
שדות: `status` (`idle | presenting | awaitingInput | won | lost`), `sequence`, `round` (1–10), `inputIndex`, `completedRounds`, `gameId`, `presentationId`, `pendingAdvance` (דגל: שחזור נכון הסתיים וממתינים למעבר לשלב הבא).

Actions (הרנדום מגיע מבחוץ בתוך ה-Action):
- `start {firstColor}` – רק מ-`idle`: רצף של צבע אחד, `round=1`, `completedRounds=0`, `gameId+1`, `presentationId+1`, → `presenting`.
- `presentationDone {id}` – רק אם `id` תואם ובמצב `presenting` ללא `pendingAdvance` → `awaitingInput`, `inputIndex=0`.
- `press {color}` – רק ב-`awaitingInput`; כל מצב אחר מתעלם:
  - צבע שגוי → `lost`, `completedRounds = round - 1`.
  - נכון ולא האחרון ברצף → `inputIndex+1`.
  - נכון והאחרון, ו-`round < 10` → `presenting` עם `pendingAdvance=true`, `completedRounds = round`, `inputIndex=0`, `presentationId+1`.
  - נכון והאחרון, ו-`round = 10` → `won`, `completedRounds = 10` (אין שלב 11).
- `advanceRound {id, nextColor}` – רק אם `id` תואם ו-`pendingAdvance`: מוסיף את הצבע לסוף הרצף, `round+1`, `pendingAdvance=false` (ה-`presentationId` לא משתנה, כדי שהמשך אותה הצגה לא יתבטל).
- `dismiss` – רק מ-`won`/`lost` → חזרה למצב ההתחלתי, תוך שמירת `gameId` ו-`presentationId` (ADR-5).
- `abandon` (זמני, יוסר ב-Milestone 3) – מ-`presenting`/`awaitingInput` חוזר למצב ההתחלתי, בלי תוצאה.

## 5. אודיו (`audio.ts`)
- `unlockAudio(): Promise<boolean>` – יוצר/מחדש `AudioContext` ומחזיר הצלחה/כשל. נקרא **ישירות מתוך הלחיצה** על "התחל משחק".
- ארבעה צלילים בגבהים שונים (Oscillator + GainNode עם Envelope קצר נגד קליקים); צליל נמשך כל עוד נדרש (לחיצה ארוכה) ונעצר בשחרור.
- שני מוטיבים: ניצחון (עולה) והפסד (יורד).
- `stopAll()` – עוצר מיד כל צליל פעיל (שימושי ל-`abandon`, ל-Unmount ולביטול הצגה).
- כשל התחלת אודיו: לא מתחילים משחק; מוצגת הודעה קצרה בעברית (**"לא הצלחנו להפעיל צליל. נסו שוב."**) מתחת לכפתור, והכפתור נשאר פעיל לניסיון חוזר. אין התקדמות שקטה.

## 6. הצגת הרצף וקלט
**הצגה (ב-`useGame`, Effect לפי `presentationId`):** `AbortController` לכל הצגה; פונקציית `wait(ms, signal)` שמפסיקה מיד בביטול; ניקוי ב-Cleanup (גם ל-Strict Mode).
- אחרי "התחל משחק": 1000ms המתנה ← לכל צבע: הארה+צליל 600ms, הפסקה 250ms (בלי הפסקה אחרי האחרון) ← `presentationDone`.
- אחרי שחזור נכון (`pendingAdvance`): 1000ms כשחיווי השלב שהושלם נשאר ← `advanceRound` (מספר השלב החדש מוצג) ← 1000ms ← הצגת כל הרצף כנ"ל.
- הקצב זהה בכל השלבים.

**לוח (`Board`):**
- מקבל `litColor` (הארה מההצגה/לחיצה), `interactive` (רק ב-`awaitingInput`), `dimmed`, `onPress`.
- בזמן הצגה: רבע מואר עם Glow והאחרים מעומעמים; בתור השחקן ובמצב התחלה/סיום: כל הצבעים מלאים.
- קלט ב-`pointerdown` (ADR-2): Pointer פעיל אחד לפי `pointerId`; מגע נוסף ו"גרירה" לרבע אחר מתעלמים עד השחרור; שחרור נקלט גם ב-`window`/`pointercancel`; הארה וצליל נמשכים לפחות 300ms או כל עוד האצבע לוחצת. מקלדת (Enter/רווח) נתמכת בהארה של 300ms.
- רבעים `disabled` כשלא `awaitingInput`, כך שלחיצות בזמן הצגה אינן משפיעות.
- מעבר הארה קצר ב-CSS בלבד; `prefers-reduced-motion` מקטין אנימציות.

**לחיצה שגויה:** מושמע מיד צליל הצבע שנלחץ; אחרי 1000ms מופיעים יחד Overlay ההפסד וצליל ההפסד.
**ניצחון:** הלחיצה האחרונה מושמעת רגיל; אחרי 1000ms מופיעים Overlay, צליל ניצחון וקונפטי.

## 7. מסך הבית (טקסטים, כולם בעברית)
- חיווי שלב: לפני משחק "שלב 1 מתוך 10"; במשחק "שלב N מתוך 10"; בסיום נשאר על השלב האחרון.
- סטטוס מתחת ללוח: הצגה – **"המשחק מציג את הרצף"**; תור השחקן – **"התור שלך"** ו-**"הקש על הצבעים לפי הסדר"**.
- כפתור "התחל משחק" רק ב-`idle`; לא מוצג במהלך משחק.
- Overlay ניצחון: **"כל הכבוד! ניצחת!"** + "אישור" + קונפטי (`canvas-confetti`, פעם אחת בכניסה ל-`won`, ניקוי ביציאה). Overlay הפסד: **"נפסלת!"** + "N שלבים שהושלמו" (0 → "0 שלבים שהושלמו", 1 → "שלב אחד שהושלם") + "אישור". ללא קונפטי בהפסד. `role="dialog"`, מיקוד אוטומטי על "אישור".
- "אישור" סוגר ומחזיר ל-`idle` ("שלב 1 מתוך 10" + "התחל משחק").

**ניווט (זמני עד Milestone 3):** מעבר ל"אודות" באמצע `presenting`/`awaitingInput` → `abandon` + `stopAll` + ביטול Timers; כשמופיעה/ממתינה הודעת סיום → `dismiss`. חזרה לבית מציגה "לפני תחילת משחק". לא נרשמת תוצאה (אין עדיין היסטוריה).

## 8. בדיקות אוטומטיות (Vitest + RTL)
- **Reducer (יחידה, בלי Mocks):** אורכי רצף 1/2/10; הרצף בכל שלב הוא קידומת של הבא (רק צבע אחד נוסף, כולל חזרה על צבע); הפסד בשלב 1 → 0; הפסד בשלב מתקדם (למשל שלב 5 → 4); ניצחון אחרי שלב 10 → 10; אין שלב 11; `press` בזמן `presenting`/`idle`/`won`/`lost` מתעלם; `presentationDone` ו-`advanceRound` עם `id` מיושן מתעלמים; `dismiss` שומר `gameId`.
- **אינטגרציה (`App`, Fake Timers, אודיו ו-`random.ts` מוחלפים):** משחק מלא עד ניצחון וקונפטי נקרא פעם אחת; הפסד ללא קונפטי; לחיצות בזמן הצגה לא משפיעות; משחק חדש אחרי "אישור" יוצר רצף חדש; קצבי ההצגה (600/250/1000); צליל לחיצה שגויה מיד ושנייה אחר כך הודעה וצליל הפסד; כשל `unlockAudio` לא מתחיל משחק ומציג הודעה; מעבר ל"אודות" באמצע משחק לא משאיר Timers/צלילים (`stopAll` נקרא, אין עדכוני מצב אחרי).
- **מגע מרובה:** אירועי `pointerdown` עם שני `pointerId` – השני מתעלם עד שחרור הראשון.
- בדיקת `npm run typecheck`, `npm run build`, `npm run test`.

## 12. סיכונים
- **אודיו במובייל:** נפתח רק מתוך Gesture; בכשל לא מתקדמים.
- **Strict Mode:** כל Effect עם Cleanup מלא, כדי שלא יתחילו שתי הצגות במקביל.
- **שחרור אצבע אחרי שהרבע הפך ל-`disabled`:** מטופל בהאזנה ב-`window`.
