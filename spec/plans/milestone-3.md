# תוכנית – Milestone 3: השהיה וחידוש משחק

מקורות: PRD §4.2–4.3, ARCHITECTURE §2.3 (סעיפים 5–7, 10, 11), §2.4, ADR-3 ו-ADR-10, DESIGN §1.1 (טבלת מצבי הבית), MILESTONES (Milestone 3). נקודת המוצא: הקוד של Milestone 2 (`gameReducer.ts`, `useGame.ts`, `App.tsx`, `HomeScreen.tsx`).

## 1. מה בונים, בפשטות
במקום לבטל משחק כשעוברים ל"אודות" — מקפיאים אותו. כשחוזרים לבית רואים "המשחק מושהה" וכפתור **"המשך משחק"**. רק לחיצה עליו מציגה שוב את כל הרצף של אותו שלב והשחקן משחזר מההתחלה. אותו כלל חל גם כשמסתירים את האפליקציה (נעילת מסך, מעבר לאפליקציה אחרת). **אין** היסטוריה (Milestone 4), **אין** PWA.

## 3. Reducer
- `GameStatus` מקבל `paused`. `GameState` מקבל שדה פנימי `resumeAs` לא נחוץ — חידוש הוא תמיד הצגה מלאה של אותו שלב.
- `pause` — רק מ-`presenting` / `awaitingInput`: עובר ל-`paused`, מאפס `inputIndex` ל-0, מעלה `presentationId` (כך שסיום הצגה מיושן מתעלמים ממנו). `sequence`, `round`, `gameId` אינם משתנים.
- **מקרה קצה (החלטה):** אם ההשהיה קרתה בשנייה שאחרי שחזור נכון, לפני שנוסף הצבע החדש (`pendingAdvance=true`) — מבטלים את ההתקדמות: `pendingAdvance=false` ו-`completedRounds = round - 1`. כך החידוש תמיד מציג את אותו שלב בשלמותו בלי צבע חדש, בדיוק כמו ב-PRD. אם הצבע החדש כבר נוסף, זו השהיה רגילה של השלב החדש.
- `resume` — רק מ-`paused`: עובר ל-`presenting` עם `presentationId` חדש, אותו רצף ואותו שלב, `pendingAdvance=false`. בלחיצה הזו אין תוספת צבע.
- `press`, `presentationDone`, `advanceRound`, `start`, `dismiss` נשארים כפי שהם; `paused` חוסם קלט (הם ממילא עובדים רק ב-`awaitingInput`/`presenting`). `pause` על `idle`/`won`/`lost`/`paused` מחזיר את המצב ללא שינוי.

## 4. Hook (`useGame`)
- `pauseGame()`: משחרר לחיצה פעילה (`releasePress`), `stopAll()`, שולח `pause`. ה-Cleanup הקיים של ה-Effect של ההצגה מבטל Timers, צליל והארה (הוא רץ כי `status`/`presentationId` משתנים) — זה המנגנון היחיד, לפי ADR-10.
- `visibilitychange` (כש-`document.hidden`) ו-`pagehide` קוראים ל-`pauseGame`. חזרה ל-visible לא עושה דבר. ה-Listeners נרשמים ב-Effect ומוסרים ב-Cleanup.
- `resumeGame()`: `await unlockAudio()` מתוך לחיצת המשתמש; בהצלחה → `resume`; בכשל → נשארים מושהים ומציגים את הודעת השגיאה הקיימת (ללא הצגה שקטה). הגנה מפני לחיצה כפולה: `resume` מתקבל רק מ-`paused`, ולכן לחיצה שנייה (אחרי שהמצב השתנה) לא עושה כלום; בנוסף דגל `resuming` ב-Ref כדי שלא ייפתחו שתי קריאות `unlockAudio` במקביל.
- **תוצאה סופית (סעיפים 10–11):** `pauseGame` במצב `won`/`lost` לא משנה את המשחק. ה-Timer של הצגת ההודעה ממשיך לרוץ גם כשנמצאים ב"אודות" (הוא חי ב-Hook, לא במסך), ולכן בחזרה לבית ההודעה מוצגת. אם ההודעה כבר הייתה פתוחה ברגע היציאה ל"אודות" → שולחים `dismiss`, וכך בחזרה רואים מצב "לפני תחילת משחק" בלי ההודעה. הצליל עצמו נשמע כשה-Timer מסתיים (גם אם כבר ב"אודות") — מאושר כנראה כפשוט ביותר; ניתן לדחות את הצליל לחזרה לבית אם תרצה.
- ה-Hook מחזיר גם `resumeGame` ו-`pauseGame` (במקום `leaveGame`).

## 5. מסך הבית
- `paused`: הלוח מעומעם ולא אינטראקטיבי, `home__status` מציג "המשחק מושהה", ובאזור הפעולה כפתור ראשי כחול **"המשך משחק"** (לפי DESIGN: "התחל משחק" סגול, "המשך משחק" כחול). חיווי השלב מציג את השלב הנוכחי (1–10).
- כפתור "המשך משחק" מופיע **רק** ב-`paused`.
- הודעת שגיאת צליל (`audioError`) מוצגת גם מתחת ל"המשך משחק".

## 6. בדיקות (Vitest)
Reducer: `pause` מ-`presenting` ומ-`awaitingInput` מאפס קלט ושומר רצף/שלב; `pause` מ-`idle`/`won`/`lost` אינו משנה; `resume` רק מ-`paused`, אותו רצף, `presentationId` חדש; מקרה הקצה של `pendingAdvance`; `press` ב-`paused` מתעלם; `presentationDone` מיושן אחרי השהיה מתעלם.
אינטגרציה: מעבר ל"אודות" באמצע הצגה ובאמצע קלט → אין הארה/צליל/Timer (`stopAll` נקרא); חזרה לבית אינה מפעילה את הרצף; "המשך משחק" מציג שוב את כל הרצף (כולל אחרי קלט חלקי) ואז מאפשר שחזור מההתחלה; `visibilitychange` ל-hidden משהה; השהיה אינה הפסד; כשל `unlockAudio` משאיר מושהה עם הודעה; לחיצה כפולה על "המשך משחק" לא מפעילה פעמיים; מעבר ל"אודות" בהמתנה אחרי לחיצה מכרעת — ההודעה מוצגת בחזרה לבית; מעבר ל"אודות" כשהודעה פתוחה — בחזרה מצב התחלה בלי הודעה.

## 7. בדיקה סופית של הבנייה
`npm run typecheck`, `npm run test`, `npm run build`, והרצה בדפדפן (אמולציית מובייל) של: השהיה באמצע הצגה, באמצע קלט, חידוש, והסתרת לשונית. רענון דף מאפס משחק (אין שמירה ב-localStorage — כבר כך).

## 8. נקודות לאישורך
1. **מקרה הקצה** (§3): השהיה בשנייה שאחרי שחזור נכון תחזיר את השחקן להתחלת אותו שלב (בלי ההתקדמות). הפשוט והעקבי עם ה-PRD.
2. **צליל הסיום** (§4): אם עוברים ל"אודות" בזמן ההמתנה, הצליל יישמע שם, וההודעה תחכה בבית.
