# תוכנית – Milestone 4: היסטוריית משחקים ומחיקה מאושרת

מקורות: PRD §4.4 ומקרי הקצה (אחסון חסום, היסטוריה ריקה, מגבלת עשר, ביטול מחיקה), ARCHITECTURE §2.3 (סעיפים 8–11), §2.5 (מודל הנתונים `HistoryData`), §2.6, ADR-4, DESIGN §1.2 + §1.3 + §2.3 (History Cards, Dialog), MILESTONES (Milestone 4). נקודת המוצא: הקוד של Milestone 3 (`App.tsx`, `useGame.ts`, `gameReducer.ts`, `AboutScreen.tsx`, `EndOverlay.tsx`/`overlay.css`).

## 1. מה בונים, בפשטות
כשמשחק נגמר (ניצחון או הפסד) נשמרת שורה אחת בזיכרון של הדפדפן (`localStorage`): מתי נגמר, כמה שלבים הושלמו, וניצחון/הפסד. במסך "אודות" רואים עד 10 משחקים אחרונים, מהחדש לישן. כפתור "מחק היסטוריה" (רק כשיש משחקים) פותח חלון אישור עם "ביטול" ו"מחק". אם האחסון לא עובד — המשחק ממשיך כרגיל ומוצגת הודעה בעברית. **אין** PWA (Milestone 5), **אין** שינוי בהתנהגות ההשהיה.

## 3. Repository (`historyStorage.ts`)
- מפתח יחיד: `simon.history.v1`. פורמט: `{ schemaVersion: 1, results: GameResult[] }` כפי שב-ARCHITECTURE §2.5 (`id`, `finishedAt` כ-ISO 8601, `completedRounds` 0–10, `outcome: 'win' | 'loss'`).
- `loadHistory()` → `{ results, error }`: אין מפתח = רשימה ריקה בלי שגיאה. JSON פגום / `schemaVersion` לא מוכר / `localStorage` זורק = רשימה ריקה + `error: 'load'`. רשומות בודדות לא תקינות (טיפוסים שגויים, `completedRounds` מחוץ ל-0–10, תאריך לא חוקי) מסוננות החוצה בשקט; מקצים רק עד 10 הראשונות.
- `addResult(current, result)` → מחזיר רשימה חדשה: הרשומה בראש + חיתוך ל-10 (הישנה ביותר נופלת), ואז כותב. מחזיר אם הכתיבה הצליחה.
- `clearHistory()` → מוחק את המפתח; מחזיר הצלחה/כישלון. **לא** מציגים רשימה ריקה אם המחיקה נכשלה.
- מזהה רשומה: `Date.now()` + מספר אקראי (לא `crypto.randomUUID`, לפי ADR-4).
- תאריך ושעה לתצוגה לפי `toLocaleString('he-IL')` בזמן המכשיר; לא נשמרת מחרוזת תצוגה.
- לא מרנדרים HTML מהאחסון (רק טקסט React רגיל).

## 4. Hook (`useHistory`) ושילוב ב-`App`
- מצב: `results`, `loadError`, `saveError`, `deleteError`. הטעינה הראשונה בזמן יצירת ה-state (initializer), כך שמסך "אודות" מראה נתונים מיד.
- `record(result)`: מוסיף דרך ה-Repository; מעדכן את הרשימה בזיכרון גם אם הכתיבה נכשלה (כדי שבפתיחת "אודות" באותה ישיבה עדיין יופיע המשחק), ומסמן `saveError` אם נכשל.
- `clear()`: אם הצליח – רשימה ריקה ו-`deleteError` נמחק; אם נכשל – הרשימה נשארת, `deleteError` מוצג.
- ב-`App`: Effect שמגיב לכניסה ל-`won`/`lost` ורושם תוצאה אחת, עם `useRef` ששומר את `gameId` האחרון שנרשם (ADR-4). בדיקה זו עומדת גם מול React Strict Mode (Effect שרץ פעמיים). `completedRounds` נלקח מה-state; `outcome` = `win`/`loss`; `finishedAt` = `new Date().toISOString()` ברגע הרישום.
- לא נרשם דבר ב-`paused`, ב-`dismiss`, במעבר מסכים או ברענון (רענון מאפס ממילא את ה-state, ה-ref מתחיל מ-0 אבל `gameId` מתחיל מ-0 ו-`idle` לא רושם).

## 5. מסך אודות
- כותרת "10 המשחקים האחרונים" נשארת. מתחתיה: רשימת `HistoryCard` (תאריך ושעה, "N שלבים שהושלמו" / "שלב אחד שהושלם", ותווית טקסט **"ניצחון"** / **"הפסד"** – הצבע בנוסף לטקסט, לא במקומו). `role="list"` / `listitem` לנגישות.
- היסטוריה ריקה: הטקסט הקיים "עדיין אין משחקים שמורים" ואין כפתור מחיקה.
- יש רשומות: כפתור משני "מחק היסטוריה" מתחת לרשימה. הרשימה גוללת בתוך המסך; פס הניווט נשאר גלוי.
- הודעות שגיאה בעברית (תחת הכותרת, `role="alert"`), למשל: "לא ניתן לטעון את ההיסטוריה", "לא ניתן היה לשמור את תוצאת המשחק", "לא ניתן היה למחוק את ההיסטוריה". הנוסח המדויק – בבנייה, קצר ופשוט. ההודעה על כשל שמירה מוצגת ב"אודות" (שם רואים היסטוריה); המשחק אינו נחסם.

## 6. חלון אישור מחיקה
- `ConfirmDialog` כשכבה בתוך מסך "אודות" (לא מסך שלישי): Scrim + כרטיס, `role="dialog"`, `aria-modal`, כותרת **"למחוק את ההיסטוריה?"**, הסבר קצר (פעולה בלתי הפיכה), כפתורים **"ביטול"** (משני) ו-**"מחק"** (אדום), מסודרים ל-RTL. הפוקוס מתחיל על "ביטול"; Escape סוגר כביטול.
- לפי DESIGN ה-Dialog ב-Mockup בהיר; בבנייה לפתוח את `spec/mockups.png` ולהתאים את המראה (אם נראה שסותר את שאר הממשק – לשאול).
- "ביטול" סוגר בלי שינוי נתונים; "מחק" קורא ל-`clear()` וסוגר; אם נכשל – מוצגת הודעה והרשימה נשארת.

## 7. בדיקות (Vitest + RTL)
**Repository:** שמירה וקריאה חוזרת; סדר חדש→ישן; אחרי 11 הוספות נשארות 10 והישנה נפלה; JSON פגום / גרסה לא מוכרת / `localStorage` זורק בקריאה → רשימה ריקה + שגיאה בלי קריסה; רשומות לא תקינות מסוננות; כתיבה שנכשלת מדווחת; מחיקה שנכשלת מדווחת.
**אינטגרציה:** ניצחון והפסד מוסיפים בדיוק רשומה אחת, עם `completedRounds` נכון (0 בהפסד בשלב 1, 10 בניצחון); ב-`StrictMode` עדיין רק רשומה אחת; השהיה, מעבר ל"אודות", `visibilitychange`, "אישור" וחזרה לבית אינם מוסיפים רשומה; רענון (רינדור חדש) באמצע משחק לא מוסיף; ההיסטוריה שנשמרה מופיעה אחרי רינדור מחדש; כרטיס מציג "ניצחון"/"הפסד"; חיווי ריק ללא כפתור מחיקה; "ביטול" לא משנה; "מחק" מרוקן ומחזיר חיווי ריק; כשל אחסון בשמירה/מחיקה מציג הודעה והמשחק ממשיך; תוצאה סופית נרשמת גם אם עברו ל"אודות" לפני הצגת ההודעה.

`npm run typecheck`, `npm run test`, `npm run build`; הרצה בדפדפן באמולציית מובייל: לשחק הפסד וניצחון, לבדוק "אודות", לרענן, לשחק 11 משחקים (אפשר באמצעות הזנת נתונים ב-DevTools) ולוודא 10 בלבד, מחיקה עם ביטול ועם אישור, וחסימת אחסון (חלון פרטי / עריכת `localStorage` פגום). לדווח לפי כל סעיף ב-Definition of Done.
